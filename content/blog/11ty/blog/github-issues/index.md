\<p>When new enhancement requests would come in to the \<a href="https://github.com/11ty/eleventy/issues/">Eleventy repository\</a>, our typical playbook would include the following:\</p> \<ol> \<li>Add a reply comment with the following:\</li> \</ol> \<blockquote> \<p>By default this repo closes new enhancement requests and places them in a queue for folks to upvote. We do this to avoid a build-up of open issues and got this idea from the lodash project\</p> \<p>Don’t forget to upvote the first comment with 👍 to register your vote! You can view \<a href="https://github.com/11ty/eleventy/issues?q=type%3A%22Vote%20Queue%22%20sort%3Areactions-%2B1-desc">the current enhancement backlog\</a>.\</p> \</blockquote> \<ol start="2"> \<li>Add a \<code>needs-votes\</code> Label to the issue.\</li> \<li>Close the issue.\</li> \</ol> \<p>This idea was via \<a href="https://samselikoff.com/">Sam Selikoff\</a> on Twitter (\<em>\<a href="https://nitter.net/samselikoff/status/991395669016436736">Archived 2018 context\</a>\</em>):\</p> \<blockquote> \<p>Recently I noticed Lodash's repo had 0 open issues. As an OSS maintainer I found this fascinating because Lodash is tremendously popular, and keeping issues down is notoriously difficult.\</p> \</blockquote> \<p>This technique was \<strong>great\</strong> and served us well for many years for the primary reason that it communicated that \<a href="https://www.zachleat.com/web/eleventy-birthday/#close-all-feature-requests">enhancement requests were classified as \<em>secondary\</em>\</a>. But it also added a nice list of things that were a possible future for the project that community folks could \<em>weigh in\</em> on.\</p> \<p>However, it also caused some confusion too: issues were closed but unimplemented. “Is the queue considered open/quasi-open/closed?” “If I still want the feature, do I need to file it again?” Folks already participating on the issue when it was placed into the queue usually understood what was happening but new folks visiting the issue later via Search may have not seen the helpful explainer comment.\</p> \<p>To make matters every so slightly worse, in \<a href="https://github.blog/changelog/2022-05-19-the-new-github-issues-may-19th-update/#%F0%9F%95%B5%F0%9F%8F%BD%E2%99%80%EF%B8%8F-issue-closed-reasons">2022 when GitHub shipped \<strong>Issue Closed Reasons\</strong>\</a> they defaulted all existing closed issues as \<em>Completed\</em>. The only alternative reason was \<em>Not planned\</em> which (to me) leaned closer towards \<em>Definitely not\</em>. I would have loved to see a \<em>Yet to be Prioritized\</em> or an \<em>Maybe, if enough folks upvote it!\</em> reason.\</p> \<p>I’m very thankful to \<a href="https://uncenter.dev/">uncenter\</a> who has gently pushed back with feedback on the above method (a few times 😅).\</p> \<h2 id="leaning-into-git-hub-discussions">Leaning into GitHub Discussions\</h2> \<p>After some very productive (in real life, what?) conversations with \<a href="https://www.abeautifulsite.net/">Cory LaViska\</a> (who recently wrote an \<a href="https://www.abeautifulsite.net/posts/how-i-use-git-hub-issues/">excellent blog post on this exact topic\</a>), it has become clear that perhaps GitHub Discussions (\<a href="https://github.blog/open-source/maintainers/create-a-home-for-your-community-with-github-discussions/">generally available in 2024\</a>) would be a more appropriate mechanism moving forward. Cory expounds thusly:\</p> \<blockquote> \<ul> \<li>Bug Report 👉 Issue\</li> \<li>Help/support 👉 Discussion\</li> \<li>Ask a question 👉 Discussion\</li> \<li>Ideas/suggestions 👉 Discussion\</li> \<li>Waxing Philosophical 👉 Discussion\</li> \</ul> \</blockquote> \<p>Cory adds to the list later in the post:\</p> \<blockquote> \<ul> \<li>Actionable Piece of Work (Milestoned Task) 👉 Issue\</li> \</ul> \</blockquote> \<p>The nice thing about GitHub Discussions is that upvoting is a first-party user interface feature in the list view. The primary downside is that we’ll lose existing vote counts in the sorted list (they’re still accessible in the full entry): it’s a \<em>level playing field moving into 2026\</em>.\</p> \<p>The other nice thing is that GitHub Issues becomes very focused to actionable work that goes into a release, not more imagination-based planning or fielding “How does this work?”-esque education requests.\</p> \<p>Feel free to watch as the previous queue is converted to the new \<a href="https://github.com/11ty/eleventy/discussions/categories/enhancement-queue">\<strong>Eleventy Enhancement Queue\</strong>\</a> (and leave your votes!).\</p> \<p>Our new issue funnels on both \<a href="https://github.com/11ty/eleventy/issues/new/choose">\<code>eleventy\</code>\</a> and \<a href="https://github.com/11ty/11ty-website/issues/new/choose">\<code>11ty-website\</code>\</a> will help you find the right place to be!\</p> \<p>Appreciate y’all!\</p>

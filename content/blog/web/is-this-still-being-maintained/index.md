\<p>I have \<em>a lot\</em> of open source projects (of varying sizes and shapes).\</p> \<p>At time of writing, I’m currently maintaining ×78 npm packages. Of those, 22 are super lightweight zero-dependency custom elements a.k.a. 🚾 Web Components (\<em>love the future compatibility I get with very little maintenance required\</em>). In addition, I also have a few \<a href="https://www.zachleat.com/domains/">active websites\</a> and starter/template projects that are open source too.\</p> \<p>I usually rotate maintenance on these and needed a way to quickly scan my little ecosystem of packages to know which ones needed love. Thus, a new little dashboard has appeared on my web site that I’m calling:\</p> \<script type="module" src="https://www.zachleat.com/static/browser-window.js">\</script> \<div>\<browser-window mode="auto" class="bw-site-theme" icon url="https://www.zachleat.com/projects/" shadow flush style="--bw-background: oklch(82.691% 0.09444 136.65);--bw-foreground: #000">\<a href="https://www.zachleat.com/projects/" class="favicon-optout">\<img alt="Screenshot image for https://www.zachleat.com/projects/" loading="lazy" decoding="async" class="" src="https://screenshot.11ty.app/https%3A%2F%2Fwww.zachleat.com%2Fprojects%2F/opengraph/" width="1200" height="630">\</a>\</browser-window>\</div> \<p>\<a href="https://www.zachleat.com/projects/" class="primarylink">\<em>Is this still being maintained??\</em>\</a>\</p> \<p>The name pays homage to those \<s>helpful\</s> passive aggressive comments folks sometimes leave on issue trackers (mirroring a fair question that perhaps I should be asking myself).\</p> \<p>Each project is given a Neglect score that represents how much love it needs. It factors popularity (via npm downloads and GitHub stars) and need (GitHub issues and pull requests, npm audits), and recency (npm publish and GitHub commit dates). It shows how many production dependencies (including transitive ones) that a project uses. It even has a little sparkline to give a little data visualization to how frequently packages are published.\</p> \<h2 id="a-broader-look">A broader look\</h2> \<p>The aggregate statistics there were genuinely surprising to me. \<em>67 million downloads in the last year\</em> (though this is heavily influenced by dependencies I maintain in Build Awesome/11ty, which are counted separately).\</p> \<p>Over 1.1k published versions, 4.7k closed issues, and 2.2k pull requests merged! \<em>(not all by me, of course)\</em>\</p> \<p>Currently my most neglected package is the \<a href="https://github.com/11ty/eleventy-plugin-vue">Eleventy Vue plugin\</a> (which owns 31 of my 42 total npm audits) and I’m actively deciding whether to revive it or retire it 🫣.\</p> \<p>\<strong>All of my 77 other packages only have 11 total npm audit reports!\</strong> I’m feeling extremely proud of that, which feels related to the work I’ve been doing to \<a href="https://www.zachleat.com/web/npm-security/">lock down publishing workflows\</a> and \<a href="https://www.11ty.dev/blog/dependency-watch/">reduce dependencies\</a>. Though that number may change over time, I now have an easy centralized place to check it. This report also makes it very obvious the relationship between dependency count and audit reports. \<a href="https://e18e.dev/">Keep reducing those dependencies, y’all!\</a>\</p> \<p>The other result of monitoring this report is that I have archived a bunch of old projects that I don’t want to track, which has a nice cleansing feeling to it.\</p>

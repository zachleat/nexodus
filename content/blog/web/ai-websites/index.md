\<style> .iframe--card { margin-block: 15vh; } \</style> \<p>Millions of \<em>Large-Language-Model\</em>-generated words have been spilled on craftsmanship in this \<strong>gilded-age of software development\</strong>. We now have agents to plan how code will be written, agents to write code, agents to review code, agents to orchestrate and dispatch tasks to other more (or less) capable subagents (these heavily subsidized tokens aren’t going to pay for themselves).\</p> \<iframe class="iframe--card" src="https://www.speedlify.dev/site/x-ai/filmstrip/" title="x.ai filmstrip" width="100%" height="360" style="border: 0" loading="lazy">\</iframe> \<p>I’ve been in this game long enough to recognize tooling improvements from software companies at the bleeding edge of technique and application and it usually goes something like this: “If we make it easier for developers to create software, they will have more bandwidth to produce higher quality software!”\</p> \<iframe class="iframe--card" src="https://www.speedlify.dev/site/openai-com/filmstrip/" title="openai.com filmstrip" width="100%" height="360" style="border: 0" loading="lazy">\</iframe> \<p>I’m always left wondering (suspecting the answer with hopeful optimism that my hunch is wrong this time): do these workflow improvements actually improve how people (technical or otherwise) \<em>experience\</em> software? Certainly \<strong>we have more software\</strong>. But is it better? I don’t know.\</p> \<iframe class="iframe--card" src="https://www.speedlify.dev/site/mistral-ai/filmstrip/" title="mistral.ai filmstrip" width="100%" height="360" style="border: 0" loading="lazy">\</iframe> \<p>Front-end web developers have lived through a few cycles of this (seven or eight years of client rendering, fifteen years of the \<em>single-page-application\</em>-era smokescreen are a few that come to mind), sold as though improvements to developer experience would cause the reanimated corpse of Ronald Reagan himself to ask you for commit access to ship trickle-down improvements to user experience.\</p> \<p>Is this cycle repeating the same playbook (on a more accelerated pace)? Certainly we’ve seen numerous recent anecdotal examples of software becoming \<em>less\</em> reliable over time (GitHub is the most recent scapegoat I’ve seen, but on my read they seem to be a second-order victim more than anything).\</p> \<p>\<em>(Seems like a great time to be in the Monitoring/Status Page business)\</em>\</p> \<iframe class="iframe--card" src="https://www.speedlify.dev/site/www-perplexity-ai/filmstrip/" title="perplexity.ai filmstrip" width="100%" height="360" style="border: 0" loading="lazy">\</iframe> \<p>With these seismic changes, I will continue to make the argument that craft defined as \<strong>caring about the quality of output\</strong> (independent of the tools used to generate the output) is \<strong>more important than ever\</strong>. Caring about what you ship will always have \<strong>real-world value\</strong> to \<s>visitors/consumers/users\</s> \<strong>real people\</strong>.\</p> \<p>\<em>Prefers-reduced-motion respecting web performance filmstrips from \<a href="https://www.speedlify.dev/group/ai/">the AI category on Speedlify\</a>, a category boasting a failing median Core Web Vitals score with 12 out of 13 sites failing Lighthouse performance and Axe accessibility checks.\</em>\</p>

\<p>\<a href="https://www.speedlify.dev/">\<img src="https://www.zachleat.com/img/built/XeWs\_v2xk7-1000.avif" alt="Speedlify2 screenshot" loading="lazy" decoding="async" width="1000" height="960">\</a>\</p> \<p>\<em>\<a href="https://www.speedlify.dev/">\<svg class="z-icon" width="1em" height="1em" viewBox="0 0 512 512">\<use href="#fas-fa-arrow-right" xlink:href="#fas-fa-arrow-right">\</use>\</svg>\<strong>\<code>speedlify.dev\</code>, now running Speedlify2\</strong>\</a>.\</em>\</p> \<p>The year is 2020. Inspired by a lack of budget for a web performance monitoring tool, the \<a href="https://www.zachleat.com/web/speedlify/">original Speedlify project\</a> \<em>(Speedlify Classic)\</em> was shipped to continuously measure site performance. It ran \<a href="https://developer.chrome.com/docs/lighthouse/">Lighthouse\</a> against a predetermined list of sites and ranked their performance against each other. Over time, I started to add a few more things to Speedlify.\</p> \<ol> \<li>A \<a href="https://www.zachleat.com/web/lighthouse-in-footer/">\<code>&lt;speedlify-score&gt;\</code> Web Component\</a> was added to show scores on your web site.\</li> \<li>The \<a href="https://www.zachleat.com/web/eleventy-leaderboard-speedlify/">Eleventy Leaderboards were migrated to use Speedlify\</a>, running 31 unique contests and testing 1208 unique websites.\</li> \</ol> \<p>As the Leaderboards grew, the work involved in maintaining them scaled similarly. Due to infrastructure build time constraints (a 15 minute build limit) and limitations in how Speedlify executed its measurement step (all sites would run serially and a compare step ran when all measurements had been taken), the Leaderboards needed to run on my own hardware.\</p> \<p>Over six years, it’s pretty natural that some folks would let their websites and domains lapse. A few sites moved away to use other tools. All of which culminated in manual work to publish Leaderboard scores. You could probably see this reflected in how often the Leaderboards were published 🫣 — though in retrospect 31 runs in six years (~2 month cadence on adverage) isn’t bad!\</p> \<h2 id="better-and-more-automated">Better and more Automated\</h2> \<p>Regardless, I’m delighted to show off some huge updates and improvements have been made to the brand new Speedlify2. Changes which will ultimately save me a bunch of time and effort!\</p> \<ul> \<li>Speedlify2 is \<em>now measuring \<strong>1565 sites\</strong>\</em> continuously without requiring any manual work.\</li> \<li>Each category has its own cadence configuration, and the Built Awesome category is currently configured to visit sites once per week to measure and test.\</li> \<li>Everything is static and self contained, deployable via GitHub Actions to GitHub Pages. You can \<a href="https://github.com/zachleat/speedlify2/">easily deploy your own Speedlify2\</a>. \<em>(Run the reset script to start from scratch)\</em>\</li> \<li>Measurements happen in small chunks in parallel on GitHub Actions. The measurement step is now decoupled from ranking. When the site builds, it pulls from the newest measurements for all steps and ranks them. This is far more robust!\</li> \<li>Sites that move away from Build Awesome (11ty) are now automatically put into an unranked Emeritus category. I went ahead and backfilled the 92 websites that have moved away since we started the showcase in 2018. Emeritus sites \<em>can\</em> show up on the Perfect Scores ranking on the home page (though at time of writing only 3 of the 92 of them do).\</li> \<li>Instead of the classic 4-circle Lighthouse design, this adds additional circles for Core Web Vitals (\<strong>field data alongside lab data\</strong>) and now explicitly shows the output of a more detailed and rigorous Axe CLI run. Lighthouse does \<em>use\</em> Axe internally but doesn’t report everything (Speedlify2 does).\</li> \<li>Adds a new \<code>&lt;speedlify2-score&gt;\</code> component.\</li> \<li>The production service has backwards API compatibility with any legacy \<code>&lt;speedlify-score&gt;\</code> components using the old speedlify.dev instance as their data source (and all sites measured there are measured on the new speedlify.dev).\</li> \<li>Categories are no longer mutually exclusive. URLs can exist in multiple categories and the home page shows all of the perfect scoring sites across all categories. To avoid extra testing traffic, single measurements are re-used across categories.\</li> \<li>Adds a new randomly selected Perfect Site of the Day.\</li> \</ul> \<p>It might be interesting to look at the report of \<a href="https://www.speedlify.dev/site/www-speedlify-dev/">Speedlify measuring Speedlify\</a>, which includes measurements before the production domain was moved from Speedlify (classic) to Speedlify2. We can see how the migration went!\</p> \<h3 id="no-javascript-comparisons">No-JavaScript Comparisons\</h3> \<p>Speedlify2 also shows screenshots for No-JavaScript and JavaScript-enabled, reporting the visual percentage difference between the two. without JavaScript, the right panel has an announcement bar and the content has shifted down" width="1000" height="529">\</picture>\</a>\</p> \<h2 id="highlighting-good-sites">Highlighting Good Sites\</h2> \<p>The \<a href="https://www.speedlify.dev/group/11ty-community/">Built Awesome Leaderboards\</a> are intended to be a very rigorous and competitive leaderboard. The sites that score well here are \<em>very\</em> fast.\</p> \<p>But (similarly to the Eleventy Leaderboards before them) we \<strong>don’t highlight bad scores\</strong>. The (exhaustively long) list is exclusive to sites with all green circles. With an exception for unknown Core Web Vitals, which requires a level of minimum production traffic in Chrome browsers to show data.\</p> \<p>Sites with yellow or red circles are shown in an overflow list (randomly ordered) with no scores visible. You can navigate through to check your site’s page individually and review the report to learn how you can improve for the next run.\</p> \<p>The other top level categories (\<a href="https://www.speedlify.dev/group/hosts/">Web Hosts\</a>, \<a href="https://www.speedlify.dev/group/ssg/">Site Generators\</a>, \<a href="https://www.speedlify.dev/group/builders/">Website Builders\</a>, \<a href="https://www.speedlify.dev/group/package-managers/">Package Managers\</a> et al) are for corporate accountability and do show poorly scoring sites. This is a separate tact we want to avoid for personal or individual websites. We can and should hold professional and paid websites to a higher standard!\</p>
